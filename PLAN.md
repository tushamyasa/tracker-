# PLAN — план реализации Salary

Опирается на [PRD-SPEC.md](PRD-SPEC.md) и [design.md](design.md). Оценки — для одного разработчика.

## Этап 0. Подготовка (0,5 дня)
- [ ] `create-next-app` (TypeScript, App Router, Tailwind, ESLint, `src/`).
- [ ] Установить: `drizzle-orm drizzle-kit @libsql/client next-auth@beta zod react-hook-form @hookform/resolvers @node-rs/argon2 recharts lucide-react sonner geist @paralleldrive/cuid2`; dev: `vitest playwright prettier`.
- [ ] Инициализировать shadcn/ui; перенести токены и шрифт Geist из design.md в `globals.css`.
- [ ] Создать БД в Turso (`turso db create salary`), токен, `.env.local` и `.env.example`.
- [ ] Git, Prettier, CI (lint + typecheck + test).

**Готово, когда:** `npm run dev` показывает пустую страницу со шрифтом Geist и обеими темами.

## Этап 1. База данных (1 день)
- [ ] `db/schema.ts` по разделу 11 SPEC; `db/client.ts` (libSQL).
- [ ] Миграции drizzle-kit, применить к Turso; локально — файл `file:local.db`.
- [ ] Данные по умолчанию: `lib/default-categories.ts`, `lib/icons.ts`, `lib/palette.ts`.
- [ ] `lib/money.ts`, `lib/dates.ts` + юнит-тесты.

**Готово, когда:** миграции применяются, тесты money/dates зелёные.

## Этап 2. Авторизация (1,5 дня)
- [ ] Auth.js v5 Credentials + JWT; `lib/auth.ts`, `api/auth/[...nextauth]`.
- [ ] `registerUser` (argon2id, транзакция: пользователь + категории по умолчанию).
- [ ] Страницы `/login`, `/register` по design.md; ошибки форм.
- [ ] `middleware.ts` для защиты маршрутов; `requireUserId()`.
- [ ] Rate limit на вход/регистрацию.
- [ ] Тесты: регистрация, дубль email, неверный пароль, редиректы.

**Готово, когда:** можно зарегистрироваться, выйти, войти; закрытые страницы недоступны без сессии.

## Этап 3. Каркас приложения (1 день)
- [ ] `(app)/layout.tsx`: левый сайдбар (≥1024), иконки (768–1023), нижний tab-bar + FAB (<768).
- [ ] Переключатель темы, меню профиля.
- [ ] Базовые UI-компоненты: Button, Input, Select, Dialog, Sheet (drawer), Table, Badge, Skeleton, Toast.

**Готово, когда:** навигация работает на 360 / 768 / 1280 px в обеих темах.

## Этап 4. Категории (1 день)
- [ ] `server/queries/categories`, `server/actions/categories`.
- [ ] Страница `/categories` с вкладками Расходы/Доходы.
- [ ] Drawer создания/редактирования: название, иконка, цвет.
- [ ] Архивация; перенос операций и удаление.
- [ ] Тесты изоляции пользователей и уникальности названия.

**Готово, когда:** CRUD категорий работает, дефолтные категории видны у нового пользователя.

## Этап 5. Операции (2 дня)
- [ ] `server/queries/transactions` (фильтры, пагинация), `server/actions/transactions`.
- [ ] Drawer добавления/редактирования (сегмент Доход/Расход, крупное поле суммы, грид категорий, дата, заметка); bottom-sheet на мобильном; FAB.
- [ ] Страница `/transactions`: таблица (десктоп) / карточки (моб.), фильтры, поиск, удаление с подтверждением.
- [ ] Проверка инварианта типа операции и категории; тесты.

**Готово, когда:** операцию можно добавить за ≤ 10 с, отредактировать, удалить, найти по фильтру.

## Этап 6. Дашборд (2 дня)
- [ ] SQL-агрегаты: `getSummary`, `getMonthlySeries`, `getExpenseByCategory`.
- [ ] Селектор периода, карточки Баланс/Доходы/Расходы с дельтой.
- [ ] График по месяцам (Recharts), donut по категориям, последние операции.
- [ ] Skeleton и пустые состояния.

**Готово, когда:** цифры на дашборде совпадают с данными операций (проверено тестами агрегатов).

## Этап 7. Отчёты, экспорт, настройки (1,5 дня)
- [ ] `/reports`: разбивка по категориям за период.
- [ ] `api/export/csv` по текущим фильтрам (с UTF-8 BOM для Excel).
- [ ] `/settings`: тема, валюта, смена пароля, удаление аккаунта.

## Этап 8. Качество и релиз (2 дня)
- [ ] E2E Playwright основного сценария.
- [ ] Аудит: Lighthouse ≥ 90, a11y, контраст в обеих темах, `prefers-reduced-motion`.
- [ ] Заголовки безопасности, проверка изоляции данных, обработка ошибок (`error.tsx`, `not-found.tsx`).
- [ ] Деплой на Vercel, env-переменные, миграции на prod Turso, бэкап-процедура.
- [ ] README: запуск, переменные, миграции.

**Итого MVP:** ≈ 12–13 рабочих дней.

## Порядок и зависимости
`0 → 1 → 2 → 3 → 4 → 5 → 6 → 7 → 8`. Этапы 4 и 5 зависят от 3; 6 — от 5; 7 — от 5–6.

## После MVP (бэклог)
Бюджеты и лимиты по категориям · повторяющиеся операции · несколько счетов и валют · вход через Google · сброс пароля по email · импорт CSV · PWA · общие бюджеты.

## Открытые решения
- Хостинг: Vercel (по умолчанию) — подтвердить.
- Rate limit: in-memory на MVP или Upstash Redis.
- Валюта: одна на пользователя (MVP) — мультивалютность в бэклоге.
