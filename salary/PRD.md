# PRD / SPEC: Веб-приложение учёта финансов «Salary»

## 1. Введение и обзор продукта (Overview)
**Salary** — это современное, быстрое и адаптивное веб-приложение для личного и семейного учёта финансов. Приложение позволяет пользователям контролировать свои доходы и расходы, классифицировать финансовые потоки по категориям, отслеживать динамику с помощью интерактивных графиков и планировать бюджет.

### 1.1. Цели продукта
- Дать пользователю понятный и быстрый инструмент ввода операций (добавление транзакции за 3-5 секунд).
- Предоставить наглядную аналитику: куда уходят деньги и откуда приходят.
- Обеспечить надёжное и изолированное хранение данных с полноценной авторизацией.
- Обеспечить высокую скорость работы благодаря архитектуре Next.js и распределённой SQLite-совместимой БД Turso (libSQL).

## 3. Архитектура и схема базы данных (Data Model)

Turso работает по протоколу libSQL. Схема реализуется через Drizzle ORM:

```
┌─────────────────┐       1:N       ┌──────────────────┐
│      users      │ ───────────────>│    categories    │
└─────────────────┘                 └──────────────────┘
        │                                    │
        │ 1:N                                │ 1:N
        ▼                                    ▼
┌─────────────────┐       N:1       ┌──────────────────┐
│   transactions  │ <───────────────┤    categories    │
└─────────────────┘                 └──────────────────┘
```

### 3.1. Таблицы базы данных

#### 1. `users` (Пользователи)
- `id` (text, primary key, uuid/nanoid / cuid2)
- `email` (text, unique, not null)
- `name` (text)
- `password_hash` (text, nullable для OAuth)
- `currency` (text, default 'RUB' / 'USD')
- `created_at` (integer/timestamp, default now)
- `updated_at` (integer/timestamp)

#### 2. `categories` (Категории)
- `id` (text, primary key)
- `user_id` (text, foreign key -> users.id, cascade delete)
- `name` (text, not null) — название категории (например: «Зарплата», «Продукты», «Аренда»)
- `type` (text: `'income'` | `'expense'`, not null)
- `color` (text, hex-код или класс Tailwind, например `#10B981`)
- `icon` (text, имя иконки из Lucide, например `shopping-cart`, `briefcase`)
- `is_default` (boolean, default false) — системные предзаполненные категории
- `created_at` (timestamp)

#### 3. `transactions` (Операции: Доходы и Расходы)
- `id` (text, primary key)
- `user_id` (text, foreign key -> users.id, cascade delete)
- `category_id` (text, foreign key -> categories.id, set null / cascade)
- `type` (text: `'income'` | `'expense'`, not null)
- `amount` (real/numeric, not null) — сумма операции
- `date` (integer/timestamp, not null) — дата совершения операции
- `note` (text, optional) — комментарий или заметка
- `created_at` (timestamp)
- `updated_at` (timestamp)

#### 4. `accounts` / `sessions` (для Auth.js / Better-Auth)
- Стандартные таблицы адаптера аутентификации.

## 4. Функциональные требования (Functional Requirements)

### 4.1. Модуль аутентификации и профиля
- Регистрация нового пользователя по Email/Пароль.
- Хеширование паролей с помощью `bcrypt` или `argon2id`.
- Авторизация и валидация сессии (защита маршрутов через Next.js Middleware).
- Автоматическое создание базового набора категорий для нового пользователя при регистрации (Seed default categories).
- Настройки профиля: смена имени, выбор основной валюты (₽, $, €, др.), сброс пароля.

### 4.2. Модуль категорий
- Разделение на два списка: **Категории доходов** и **Категории расходов**.
- Создание новой категории с выбором:
  - Названия;
  - Типа (`income` / `expense`);
  - Цвета из палитры;
  - Иконки из каталога (Lucide Icons).
- Редактирование и удаление категории.
- Безопасное удаление: если у категории есть привязанные транзакции, предоставить выбор: перенести в категорию «Другое» или удалить вместе с транзакциями.

### 4.3. Модуль учёта транзакций (Salary Tracker Core)
- Быстрое добавление транзакции:
  - Выбор типа: Доход / Расход;
  - Ввод суммы (удобная цифровая клавиатура на мобильных, валидация положительного числа);
  - Выбор категории (с визуальным превью иконки и цвета);
  - Выбор даты и времени (по умолчанию — текущие);
  - Дополнительное примечание (note).
- Просмотр ленты операций с группировкой по дням.
- Фильтрация:
  - По периоду (Сегодня, Текущая неделя, Текущий месяц, Произвольный диапазон);
  - По типу (Все / Доходы / Расходы);
  - По конкретным категориям;
  - Текстовый поиск по заметкам.
- Редактирование и удаление любой операции.

### 4.4. Дашборд и Аналитика (Dashboard & Reports)
- **Информационные плашки (KPI Cards) & Главный акцент:**
  - Крупный общий текущий баланс с дельтой к прошлому месяцу (главный визуальный якорь экрана).
  - Кнопка-глазок «Режим приватности» (мгновенное скрытие/показ сумм звёздочками `••••••`).
  - Сумма доходов за выбранный период (зелёный акцент).
  - Сумма расходов за выбранный период (красный акцент).
- **Визуализация и UX:**
  - Glassmorphism-стилистика карточек и графиков (Recharts).
  - Круговая диаграмма (Donut Chart) распределения расходов по категориям.
  - Гистограмма (Bar Chart) сравнения доходов и расходов помесячно.
  - Адаптивная навигация: фиксированный левый сайдбар на десктопе и нижний Bottom Tab Bar с быстрой кнопкой добавления на мобильных.
- Быстрый топ категорий с наибольшими тратами.

## 5. Нефункциональные требования (Non-Functional Requirements)

1. **Производительность:** Время начальной отрисовки (FCP) < 1.0s, мгновенные переходы между страницами с использованием Server Components и Suspense.
2. **Безопасность:**
   - Multi-tenant изоляция: каждый SQL-запрос строго фильтруется по `user_id` текущей сессии.
   - Защита от CSRF, XSS (встроенная в Next.js).
   - Rate limiting на эндпоинты авторизации.
3. **Адаптивность (Responsive Design):** Идеальная работа на смартфонах (320px+), планшетах и десктопах (1920px+).
4. **Offline / PWA готовность:** Поддержка манифеста PWA для установки приложения на рабочий стол мобильного устройства как приложение.

## 6. План и фазы реализации (Implementation Roadmap)

### Фаза 1: Инициализация и БД (Sprint 1)
- Инициализация проекта `Next.js 15` (TypeScript, Tailwind, ESLint).
- Подключение Turso через `@libsql/client` и настройка `drizzle-orm`.
- Описание схемы БД (users, categories, transactions) и выполнение первых миграций.
- Настройка `shadcn/ui` и базовой темы оформления.

### Фаза 2: Аутентификация (Sprint 2)
- Настройка авторизации (Auth.js / Better-Auth).
- Создание страниц `/login` и `/register`.
- Middleware для защиты роутов `/(dashboard)/*`.
- Функция автогенерации начальных категорий при первом входе.

### Фаза 3: Управление категориями и CRUD транзакций (Sprint 3)
- Страница `/categories`: создание, редактирование, удаление категорий, палитра цветов и иконки.
- Server Actions для работы с категориями с валидацией Zod.
- Компонент модального окна добавления дохода/расхода.
- Страница `/transactions`: история, фильтры, сортировка, удаление/редактирование.

### Фаза 4: Дашборд и Визуальная аналитика (Sprint 4)
- Главная страница `/dashboard`: карточки баланса, графики Recharts.
- Аналитические фильтры (за месяц, квартал, год).
- Виджет быстрого добавления операции.

### Фаза 5: Полировка, UX и деплой (Sprint 5)
- Интеграция финализированного дизайна из `design.md`.
- Анимации переходов (`framer-motion`), скелетоны загрузки (`loading.tsx`), empty states.
- Развёртывание на Vercel с привязкой к продакшн-базе Turso.
