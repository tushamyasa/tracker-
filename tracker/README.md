# Трекер тренировок

Веб-приложение для записи тренировок: подходы, таймер отдыха, рекорды, графики прогресса, шаблоны, замеры тела и достижения. Интерфейс на русском и английском, светлая и тёмная темы, mobile-first.

Документация проекта лежит рядом, в корне репозитория: [PRD-SPEC.md](../PRD-SPEC.md), [design.md](../design.md), [PLAN.md](../PLAN.md).

## Стек

Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS 4, Prisma 6 + PostgreSQL, next-intl, Recharts, Radix UI, Vitest, Playwright.

## Быстрый старт

Нужен Node.js 22 или новее.

```bash
npm install
cp .env.example .env   # задайте SESSION_SECRET (не короче 16 символов)
npm run db:local         # в отдельном окне терминала: локальный PostgreSQL, держите окно открытым
npm run db:setup         # миграции и 112 стартовых упражнений (один раз)
npm run dev              # http://localhost:3000
```

Локальный PostgreSQL здесь — это PGlite, то есть настоящий PostgreSQL в WebAssembly: устанавливать ничего не нужно, данные лежат в папке `.pglite`. Если у вас уже есть свой PostgreSQL, пропустите `db:local` и укажите его адрес в `DATABASE_URL`.

По умолчанию (`AUTH_MODE=open`) вход идёт по любому email, даже вымышленному, без пароля и без подтверждения: новый адрес создаёт аккаунт. Для публичного запуска включите вход по ссылке из письма, см. раздел «Вход по ссылке из письма».

## Скрипты

| Команда | Что делает |
|---------|-----------|
| `npm run dev` | dev-сервер |
| `npm run build` / `npm start` | production-сборка и запуск |
| `npm run lint` | ESLint |
| `npm test` | юнит-тесты (Vitest) |
| `npm run test:e2e` | e2e-тесты (Playwright): сами собирают и запускают приложение |
| `npm run db:local` | локальный PostgreSQL (PGlite) для разработки; `-- --memory` — без сохранения данных |
| `npm run db:setup` | применить миграции и загрузить системные упражнения |
| `npm run db:migrate` | новая миграция в разработке |
| `npm run db:seed` | загрузка системных упражнений (повторный запуск безопасен) |

Перед первым запуском e2e: `npx playwright install chromium`. E2E и юнит-тесты сами поднимают временный PostgreSQL в памяти, применяют миграции и ничего не пишут в вашу рабочую базу, поэтому `db:local` для них запускать не нужно.

## Устройство

```
src/
  app/
    (auth)/        вход и онбординг
    (app)/         защищённая часть: главная, упражнения, шаблоны, тренировки,
                   прогресс, замеры тела, достижения, профиль
    api/           экспорт данных, выдача загруженных фото
  components/      UI-кит (ui/) и компоненты разделов
  lib/             чистая логика: рекорды, XP и серии, единицы, CSV, фильтры
  server/          server actions и сессия
prisma/            схема, миграции, сид
messages/          словари ru.json и en.json
tests/  e2e/       юнит- и e2e-тесты
```

Ключевые решения:

- **Сессия:** подписанный JWT в httpOnly cookie на 30 дней. Каждая операция проверяет владельца записи.
- **Единицы:** вес хранится в килограммах, обхваты в сантиметрах. Пользователям с фунтами показываются фунты и дюймы.
- **Производные данные считаются из истории:** рекорды, XP, уровень и серия не хранятся счётчиками, а пересчитываются по подходам. После правки или удаления тренировки всё остаётся согласованным. Исключение — открытые достижения: полученное остаётся.
- **Дни и недели** считаются по UTC.
- **Одна активная тренировка** на пользователя гарантирует частичный уникальный индекс в базе.
- **Ограничение частоты** (вход, запросы ссылок) считается в таблице `RateLimit` одним атомарным запросом, поэтому работает и на serverless-платформах, где запросы обслуживают разные экземпляры.
- **Фото упражнений:** если задан `BLOB_READ_WRITE_TOKEN`, они хранятся в Vercel Blob, иначе в папке на диске. В обоих случаях отдаёт их маршрут `/api/media`, который проверяет владельца.

## Экспорт данных

В профиле: полный архив JSON, CSV подходов и CSV замеров тела (`/api/export?format=json|csv`, для замеров `&data=measurements`). Значения, похожие на формулы, в CSV экранируются.

## Деплой

Приложению нужны PostgreSQL и, для фото, постоянное хранилище файлов. Подходят два пути.

### Vercel

Фото на Vercel хранятся в Vercel Blob, база PostgreSQL создаётся в Storage. Сборка уже настроена: скрипт `vercel-build` сам применяет миграции перед сборкой.

1. Запушьте код на GitHub.
2. На vercel.com: **Add New → Project** → выберите репозиторий. Фреймворк определится как Next.js. Если приложение лежит в подпапке репозитория, укажите её в **Root Directory**.
3. В проекте откройте **Storage** и создайте базу PostgreSQL (Neon через Marketplace) и хранилище **Blob**. Блок Blob создавайте с доступом **Private**. Vercel добавит в проект переменные `DATABASE_URL` и `BLOB_READ_WRITE_TOKEN`. Если у Blob выбран публичный доступ, добавьте `BLOB_ACCESS=public`.
4. Для пулов подключений (адреса вида `…-pooler…`) в конец `DATABASE_URL` должно быть дописано `?pgbouncer=true` (и `&connect_timeout=15`). Для миграций это не мешает.
5. В **Settings → Environment Variables** добавьте:
   - `SESSION_SECRET`: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`;
   - `AUTH_MODE=email`, `APP_URL=https://ваш-домен`, `SMTP_URL`, `MAIL_FROM`: вход по ссылке из письма (без них вход будет по любому адресу без подтверждения);
6. Нажмите **Deploy**. Пока сборка идёт, `prisma migrate deploy` создаст таблицы.
7. Один раз загрузите стартовые упражнения с вашего компьютера, подставив адрес боевой базы из Vercel (Storage → база → `.env.local`); сам адрес не сохраняйте в файлах репозитория:

```bash
DATABASE_URL="postgresql://…" npm run db:seed
```

8. Откройте `https://ваш-домен/api/health`: должно быть `{"status":"ok"}`.

Ограничения на Vercel: размер фото до 2 МБ (потолок тела запроса к функции 4,5 МБ), лимиты бесплатного тарифа Blob и базы смотрите у провайдера.

### Свой сервер (VPS)

Приложение работает как обычный Node.js-процесс. Нужны PostgreSQL (свой или управляемый) и постоянный диск под фото (`UPLOAD_DIR`). Собирать нужно на самом сервере (или на машине с той же ОС): Prisma ставит движок под текущую платформу.

```bash
git clone <репозиторий> && cd tracker
npm ci
cp .env.example .env     # задайте DATABASE_URL, SESSION_SECRET, UPLOAD_DIR и параметры входа по ссылке
npx prisma migrate deploy
npm run db:seed
npm run build
npm start                # порт 3000, переменная PORT меняет порт
```

### Переменные окружения

| Переменная | Обязательна | Назначение |
|------------|-------------|-----------|
| `DATABASE_URL` | да | адрес PostgreSQL, `postgresql://пользователь:пароль@хост:5432/база` |
| `SESSION_SECRET` | да | случайная строка от 32 символов; в production заглушку приложение не примет |
| `BLOB_READ_WRITE_TOKEN` | на Vercel | включает хранилище фото Vercel Blob; без него фото пишутся на диск |
| `BLOB_ACCESS` | нет | `private` (по умолчанию) или `public`: как создано хранилище Blob |
| `UPLOAD_DIR` | на своём сервере | папка фото на постоянном диске (без Blob) |
| `AUTH_MODE` | рекомендуется | `open` (по умолчанию) или `email`: вход по ссылке из письма |
| `APP_URL` | при `AUTH_MODE=email` | публичный адрес приложения, например `https://tracker.example.com`; из него строятся ссылки в письмах |
| `SMTP_URL` | при `AUTH_MODE=email` | например `smtps://user:pass@smtp.example.com:465` |
| `MAIL_FROM` | нет | адрес отправителя |
| `AUTH_RATE_LIMIT` | нет | попыток входа в минуту с одного адреса в режиме `open`, по умолчанию 30 |
| `AUTH_LINK_EMAIL_LIMIT` / `AUTH_LINK_IP_LIMIT` | нет | писем со ссылкой за 15 минут на один адрес (по умолчанию 5) и с одного IP (20) |

### Что ещё нужно

- **HTTPS.** На Vercel он есть из коробки. На своём сервере поставьте перед приложением обратный прокси (Caddy, nginx), который терминирует TLS и передаёт заголовок `X-Forwarded-For`: по нему считается лимит попыток входа. Cookie сессии получает флаг `secure` в production, поэтому по чистому http вход работать не будет.
- **Автозапуск** (свой сервер). Запускайте `npm start` под systemd или pm2.
- **Мониторинг.** `GET /api/health` отвечает 200, если база доступна, и 503 при сбое; вход не требуется.
- **Резервные копии.** Управляемые базы (Neon, Supabase) делают копии сами, проверьте срок хранения в тарифе. На своём сервере: `pg_dump "$DATABASE_URL" -Fc -f backup.dump` и копия папки `UPLOAD_DIR`. Blob хранится у провайдера.
- **Обновление.** `git pull && npm ci && npx prisma migrate deploy && npm run build`, затем перезапуск процесса. На Vercel достаточно пуша в репозиторий.

Шаблоны для своего сервера (systemd-юнит, Caddyfile, скрипт копирования, пример переменных) лежат в папке [deploy](deploy/). На реальном сервере я их не запускал.

## Вход по ссылке из письма

В режиме `AUTH_MODE=email` пароль и вход по «любому адресу» отключены. Пользователь вводит email, на него приходит одноразовая ссылка, аккаунт создаётся после её открытия. Так подтверждается владение почтой.

Как это устроено:

- токен случайный (32 байта), в базе хранится только его SHA-256, срок действия 15 минут, использовать можно один раз;
- открытие ссылки токен **не** расходует: вход завершается нажатием кнопки на странице подтверждения, поэтому почтовые сканеры и предпросмотр ссылок не «сжигают» токен;
- погашение атомарно, при параллельных запросах проходит только один;
- ответ на запрос ссылки одинаков для новых и существующих адресов, аккаунты не перечисляются;
- лимиты: 5 писем за 15 минут на адрес и 20 на IP;
- аккаунт не создаётся, пока ссылка не открыта, поэтому чужие адреса не засоряют базу.

Для отладки без SMTP: `MAIL_TRANSPORT=console` печатает письма в лог сервера (на Vercel — в Runtime Logs), `MAIL_TRANSPORT=file` кладёт их JSON-файлами в `MAIL_OUTBOX_DIR` (так работают e2e-тесты). Без `SMTP_URL` по умолчанию используется `console`.

## Безопасность

Что сделано: подписанная httpOnly-сессия, проверка владельца при каждой операции, валидация всех входов (zod), заголовки безопасности и CSP в production, проверка содержимого загружаемых картинок по сигнатуре, доступ к фото только владельцу (в том числе в Blob), ограничение частоты входа в базе, экранирование формул в CSV, удаление фото вместе с аккаунтом.

Главный риск режима `AUTH_MODE=open`: **вход по email без подтверждения**. Любой, кто знает чужой адрес, получит доступ к его аккаунту. Для личного и демонстрационного использования это допустимо, в production приложение напишет предупреждение в лог. Для публичного запуска используйте `AUTH_MODE=email`: он подтверждает владение почтой.

Остальные ограничения: сессию нельзя отозвать на сервере до истечения 30 дней (выход удаляет только cookie), лимит входа привязан к заголовкам прокси (на Vercel это `x-forwarded-for`) и не защищает от распределённых атак, CSP допускает `unsafe-inline` для скриптов и стилей, как того требует Next.js без nonce.

## Проверка релиза

Критерии приёмки из PRD-SPEC (раздел 15), результат на локальной production-сборке:

| Критерий | Результат |
|----------|-----------|
| Вход с вымышленным email создаёт аккаунт, повторный вход открывает тот же | e2e `auth.spec.ts` (режим `open`) |
| Вход по ссылке: одноразовость, подделка, лимиты, язык письма | e2e `email/login.spec.ts` и юнит-тесты токенов и SMTP |
| Шаблон → тренировка → 3 подхода → завершение → тренировка в истории | e2e `workout.spec.ts`, `history.spec.ts` |
| Обновление страницы посреди тренировки не теряет данные | e2e `workout.spec.ts` |
| Рекорд помечается PR и появляется в прогрессе | e2e `progress.spec.ts` |
| Язык и тема сохраняются после перезагрузки | e2e `security.spec.ts` |
| Пользователь A не видит и не меняет данные пользователя B | e2e во всех наборах (404 и 401) |
| Экспорт отдаёт корректные CSV и JSON | e2e `export.spec.ts` |
| Lighthouse mobile: Performance ≥ 85, Accessibility ≥ 95 | 98–100 и 98–100 на 9 страницах (локально, эмуляция мобильного) |
| Нет ошибок в консоли на основных экранах | e2e `quality.spec.ts` |

Lighthouse запускался на локальном сервере с эмулированным мобильным профилем (тогда база была SQLite); на реальном хостинге цифры зависят от сети и базы, поэтому после деплоя проверку стоит повторить.

После перехода на PostgreSQL тесты (107 юнит и 96 e2e) идут на PGlite: это настоящий PostgreSQL, собранный в WebAssembly, а не отдельный сервер. На управляемом PostgreSQL (Neon, Supabase) их я не гонял, поэтому после первого деплоя пройдите вход, запись тренировки и загрузку фото вручную.
