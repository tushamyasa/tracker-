# Трекер тренировок

Веб-приложение для записи тренировок: подходы, таймер отдыха, рекорды, графики прогресса, шаблоны, замеры тела и достижения. Интерфейс на русском и английском, светлая и тёмная темы, mobile-first.

Документация проекта лежит рядом, в корне репозитория: [PRD-SPEC.md](../PRD-SPEC.md), [design.md](../design.md), [PLAN.md](../PLAN.md).

## Стек

Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS 4, Prisma 6 + SQLite, next-intl, Recharts, Radix UI, Vitest, Playwright.

## Быстрый старт

Нужен Node.js 22 или новее.

```bash
npm install
cp .env.example .env        # задайте SESSION_SECRET (не короче 16 символов)
npx prisma migrate deploy   # создаёт базу prisma/dev.db
npm run db:seed             # 112 стартовых упражнений
npm run dev                 # http://localhost:3000
```

Вход по любому email, даже вымышленному, без пароля и без подтверждения. Новый адрес создаёт аккаунт.

## Скрипты

| Команда | Что делает |
|---------|-----------|
| `npm run dev` | dev-сервер |
| `npm run build` / `npm start` | production-сборка и запуск |
| `npm run lint` | ESLint |
| `npm test` | юнит-тесты (Vitest) |
| `npm run test:e2e` | e2e-тесты (Playwright): сами собирают и запускают приложение |
| `npm run db:migrate` | новая миграция в разработке |
| `npm run db:seed` | загрузка системных упражнений (повторный запуск безопасен) |

Перед первым запуском e2e: `npx playwright install chromium`. E2E создают в локальной базе вымышленных пользователей; на данные это не влияет, но базу можно удалить (`prisma/dev.db`) и создать заново.

## Устройство

```
src/
  app/
    (auth)/        вход и онбординг
    (app)/         защищённая часть: главная, упражнения, шаблоны, тренировки,
                   прогресс, замеры тела, достижения, профиль
    api/           экспорт данных, выдача загруженных фото
  components/      UI-кит (ui/) и компоненты разделов
  lib/             чистая логика: рекорды, XP и серии, единицы, CSV, фильтры
  server/          server actions и сессия
prisma/            схема, миграции, сид
messages/          словари ru.json и en.json
tests/  e2e/       юнит- и e2e-тесты
```

Ключевые решения:

- **Сессия:** подписанный JWT в httpOnly cookie на 30 дней. Каждая операция проверяет владельца записи.
- **Единицы:** вес хранится в килограммах, обхваты в сантиметрах. Пользователям с фунтами показываются фунты и дюймы.
- **Производные данные считаются из истории:** рекорды, XP, уровень и серия не хранятся счётчиками, а пересчитываются по подходам. После правки или удаления тренировки всё остаётся согласованным. Исключение — открытые достижения: полученное остаётся.
- **Дни и недели** считаются по UTC.
- **Одна активная тренировка** на пользователя гарантирует частичный уникальный индекс в базе.

## Экспорт данных

В профиле: полный архив JSON, CSV подходов и CSV замеров тела (`/api/export?format=json|csv`, для замеров `&data=measurements`). Значения, похожие на формулы, в CSV экранируются.

## Деплой на свой сервер

Приложение работает как обычный Node.js-процесс с базой SQLite в одном файле. Подойдёт VPS или любой сервер с постоянным диском. Платформы с эфемерной файловой системой (например, Vercel) не подходят, пока база SQLite: для них нужно перейти на PostgreSQL (в Prisma меняется провайдер в `schema.prisma`).

Собирать нужно на самом сервере (или на машине с той же ОС), потому что Prisma ставит бинарный движок под текущую платформу.

```bash
git clone <репозиторий> && cd tracker
npm ci
cp .env.example .env     # задайте DATABASE_URL (абсолютный путь), SESSION_SECRET, UPLOAD_DIR
npx prisma migrate deploy
npm run db:seed
npm run build
npm start                # порт 3000, переменная PORT меняет порт
```

Переменные окружения:

| Переменная | Обязательна | Назначение |
|------------|-------------|-----------|
| `DATABASE_URL` | да | `file:/абсолютный/путь/app.db` на постоянном диске |
| `SESSION_SECRET` | да | случайная строка от 32 символов; в production заглушку приложение не примет |
| `UPLOAD_DIR` | рекомендуется | папка загруженных фото на постоянном диске |
| `AUTH_RATE_LIMIT` | нет | попыток входа в минуту с одного адреса, по умолчанию 30 |

Что ещё нужно:

- **HTTPS.** Поставьте перед приложением обратный прокси (Caddy, nginx), который терминирует TLS и передаёт заголовок `X-Forwarded-For`: по нему считается лимит попыток входа. Cookie сессии получает флаг `secure` в production, поэтому по чистому http вход работать не будет.
- **Автозапуск.** Запускайте `npm start` под systemd или pm2.
- **Мониторинг.** `GET /api/health` отвечает 200, если база доступна, и 503 при сбое; вход не требуется.
- **Резервные копии.** Копируйте файл базы и папку `UPLOAD_DIR`. Для базы лучше `sqlite3 app.db ".backup 'копия.db'"`, чтобы копия была согласованной при работающем приложении.
- **Обновление.** `git pull && npm ci && npx prisma migrate deploy && npm run build`, затем перезапуск процесса.
- **Один экземпляр.** Лимит попыток входа хранится в памяти процесса, а SQLite рассчитана на один сервер. Горизонтальное масштабирование потребует PostgreSQL и общего хранилища для лимитов и фото.

## Безопасность

Что сделано: подписанная httpOnly-сессия, проверка владельца при каждой операции, валидация всех входов (zod), заголовки безопасности и CSP в production, проверка содержимого загружаемых картинок по сигнатуре, доступ к фото только владельцу, ограничение частоты входа, экранирование формул в CSV, удаление фото вместе с аккаунтом.

Главный риск, принятый осознанно: **вход по email без подтверждения**. Любой, кто знает чужой адрес, получит доступ к его аккаунту. Для личного и демонстрационного использования это допустимо. Перед публичным запуском нужно подтверждение владения почтой (magic link или пароль).

Остальные ограничения: сессию нельзя отозвать на сервере до истечения 30 дней (выход удаляет только cookie), лимит входа привязан к заголовкам прокси и не защищает от распределённых атак, CSP допускает `unsafe-inline` для скриптов и стилей, как того требует Next.js без nonce.

## Проверка релиза

Критерии приёмки из PRD-SPEC (раздел 15), результат на локальной production-сборке:

| Критерий | Результат |
|----------|-----------|
| Вход с вымышленным email создаёт аккаунт, повторный вход открывает тот же | e2e `auth.spec.ts` |
| Шаблон → тренировка → 3 подхода → завершение → тренировка в истории | e2e `workout.spec.ts`, `history.spec.ts` |
| Обновление страницы посреди тренировки не теряет данные | e2e `workout.spec.ts` |
| Рекорд помечается PR и появляется в прогрессе | e2e `progress.spec.ts` |
| Язык и тема сохраняются после перезагрузки | e2e `security.spec.ts` |
| Пользователь A не видит и не меняет данные пользователя B | e2e во всех наборах (404 и 401) |
| Экспорт отдаёт корректные CSV и JSON | e2e `export.spec.ts` |
| Lighthouse mobile: Performance ≥ 85, Accessibility ≥ 95 | 98–100 и 98–100 на 9 страницах (локально, эмуляция мобильного) |
| Нет ошибок в консоли на основных экранах | e2e `quality.spec.ts` |

Lighthouse запускался на локальном сервере с эмулированным мобильным профилем; на реальном хостинге цифры зависят от сети и сервера, поэтому после деплоя проверку стоит повторить.

## Что не сделано

Из PRD отложено: офлайн-режим и service worker, push-напоминания, программы на несколько недель с автопрогрессией, суперсеты, калькулятор блинов, импорт из Hevy/Strong, шеринг-карточки, фото и GIF техники для системных упражнений (нужен источник с подходящей лицензией). Манифест и иконки для установки на экран телефона есть.
